# Design

## Context

坐标在数据层本来就没有边界：`normalizeNode` 接受任何有限数，负数照存。唯一的夹子在面板拖拽那一步——`Math.max(0, …)` 把坐标截在非负区间。平移从头到尾不夹，缩放限定在 0.35–2.4。

视口由 `styles.board` 的三行决定：`width: 100%`、`maxWidth: 660`、`aspectRatio: 1 / 1`，外面套 `overflow: hidden`。列表用的是同一个 660 上限。

自动布局（`layoutOf`）只给没有坐标的节点算默认位置，从 `(16, 16)` 起；它顺带算出来的 `width` / `height` 现在没人读。

这次没有 Host 侧改动，也没有可离线回归的部分：`client.js` 依赖宿主的 React，离线起不来。

## Goals / Non-Goals

**Goals:**

- 节点能拖到面板看得见的任何地方，包括原点左上方的负坐标。
- 画布横向用满面板，纵向不抢面板的剩余高度。

**Non-Goals:**

- 不做 fit-to-content、小地图、键盘平移。
- 不改缩放范围，不改平移手感。
- 不把列表挪成抽屉——列表还在画布下面。
- 不加撤销。

## Decisions

### 只去掉夹子，不加新的边界

`Math.max(0, …)` 去掉就是完整的修法；再加一个"最大坐标"只是同一个 bug 换个数。副作用是节点可以被拖到很远（比如 `-100000`），下次打开找不回来——但往右下拖到 `100000` 本来也是一样的结果，这次没有新增这类风险。

### 高度仍由宽度定

保留 `aspectRatio: 1 / 1`，只去掉 `maxWidth: 660`。这样画布横向用满面板，纵向跟着宽度走，不占面板的剩余高度。

**备选**：画布高度 = 面板剩余高度（`flex: 1`）。否决——那会挤掉列表并改变整个面板的滚动模型，不是这次要的。

### 列表宽度跟着一起放开

两处都写着 `maxWidth: 660`。画布 1200 宽、列表 660 宽会左右不齐，所以一起改；这不是功能改动，只是对齐。

### 不动 `layoutOf` 的默认落位

它只影响"还没有坐标"的节点。让默认落位留在正区更符合直觉：新节点出现在原点附近，而不是某个负偏移。已有坐标的节点完全不受影响。

代价是：节点被拖到负区之后，新加的格子还在正区，两者可能离得很远。这是"没有 fit 功能"的已知缺口，这次不做。

## Risks / Trade-offs

- **面板很宽时正方形会很高**：宽 1200 的面板会得到 1200 高的画布，底部要滚动才看得到。真嫌高就以后再加一个高度上限，这次不提前发明。
- **拖得太远找不回来**：没有 fit-to-content。现有的缓解是缩放 chip 点一下把视角复位到 `(24, 24)`、100%，能看到原点附近的节点；负区深处的节点仍然要自己平移过去。
- **没有自动化验证**：这是纯面板改动，离线回归脚本覆盖不到。验收方式是按一层清单手动看一眼（拖到负区、刷新后位置不变、宽面板填满），并把这条写进 tasks，别让人以为有测试保护。
