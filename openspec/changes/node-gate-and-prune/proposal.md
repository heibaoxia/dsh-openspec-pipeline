# Proposal

## Why

画布上现在有两种格子会一直占着地方，而且没人拦：

一种 change 已经进了 `archive/`，它永远不会再跑，只能一格一格右键删；另一种 proposal 还没写完、连 `tasks.md` 都没有，点「开始」时插件照样给它开一个对话，让那边的 Agent 凭空开工。前者是垃圾，后者是半成品，两种都不是「能执行」的格子，但插件对它们和对正常格子的处理一模一样。

## What Changes

- **没达到执行标准的格子不再开跑。** 拉对话之前先看这一格能不能跑：change 目录还在、有任务清单、规划写完了（`openspec status` 读不到时不看这一条）。不够格的不开对话，记「等你」并写明差什么。
- **写好了自动放行，不用人再点一次。** 等写好的格子和等归档走同一个等待机制：这一轮不退出，格子够格了就放回「待跑」接着往下跑；等待期间它被归档的，直接补记完成。
- **手动「启动」用同一把尺子。** 不够格就拒绝，并把差什么写在按钮下面。
- **一键清理已归档的格子。** 画布上有永远不可能再跑的格子时，角落出现一个「清理 N」，点一下全删掉，连带摘掉下游指向它们的线；正在等归档、正在跑、还没写好的格子不在清理范围内。同一个动作也给 Agent 用（工具加一个 `prune`）。
- **Agent 不能把已归档的 change 画回图里。** `wire` 点名一个只在 `archive/` 里的 change 时跳过并在回报里写明「没加，已经归档了」；`plan` 的声明里出现已归档或仓库里找不到的名字时整单拒绝。
- **没写完的 change 仍然可以进图。** 占位格子有用：能让人一眼看见「这批还差三份提案」。它只是不能被拉起来执行。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `node-run`: 开跑前多一道「写好了没有」的闸。不够格的不进对话，改成持续等待并在写完时自动放行；手动「启动」同样受这道闸约束。
- `pipeline-graph`: 新增「清理不可执行的格子」这个图操作：只删已归档和已找不到的格子，连带摘掉下游的线，运行中也允许。
- `wire`: 点名已归档的 change 从「合法」改成「跳过并回报」；`plan` 补上与 `wire` 同口径的名字校验。

## Impact

- `lib/index.js`：runner 的调度循环（新增一组等待）、`runNode` 的前置判断、`start-node` 的拒绝条件、`wireGraph` 与 `plan` 的名字校验、新的 `prune` 动作（工具枚举 + HTTP 入口）。
- `lib/client.js`：画布上的「清理 N」入口、清理后的提示、节点上区分「等归档」和「等写好」、待处理列表不再给没写完的格子配「归档」按钮。
- `test/`：新增两个离线回归 —— 等写好自动放行、清理只碰终态格子。
- README：面板一节补新入口和新状态；`wire` 一节的名字校验口径要改。
