# Design

## Context

`snapshot()` 已经把整个 `supervisor` 对象下发给面板（`enabled`、`sessionId`、`lastAt`、`lastNote`，以及 `fix-supervisor-prompt-signal` 引入的 `lastError`）。面板现在只读 `enabled` 和 `sessionId`，另外三个字段从来没被读过。

这一行是常驻的（不用翻「⋯」），高度固定，塞不下多行日志；所以设计问题是「一句话怎么把三件事说清」，不是「放多少信息」。

## Goals / Non-Goals

**Goals:**

- 开着的时候，这一行能回答「它上次动手了没有、为了什么、成没成」。
- 失败和成功在同一行里一眼可分，不用读完整句话。

**Non-Goals:**

- 不做监工的执行历史列表（要看过程就点「打开对话」）。
- 不新增状态字段，不改 host 半身。

## Decisions

### 一行三段：状态词 + 时间 + 结论

渲染成 `值班中 · 12:03 投过值班单 · N3 停住了` 这种形状。没有 `lastAt` 时第二段省略，换成「还没出过手」。`lastError` 非空时第三段换成红色的失败原因，状态词仍然是「值班中」——监工开着才是事实，上一次投递失败是另一件事，不该把开关状态也染红。

备选：把失败做成整行红底。放弃的原因是它会让人以为监工已经停了，从而去点一次「停用/启用」，反而打断它。

### 时间只在客户端格式化

状态里是 ISO 字符串（`toISOString()`）。面板用 `new Date(iso).toLocaleTimeString('zh-CN', { hour: '2-digit', minute: '2-digit' })` 显示；解析失败时显示原串，不显示 `Invalid Date`。

备选：host 侧就把时间格式化好再下发。放弃的原因是 host 不知道面板所在时区，而且同一个状态还有别的消费方（工具返回、另一个面板）。

### 文案由 `lastNote` 提供，客户端不再拼接语义

`lastNote` 存的是值班单标题（例如「N3 停住了：对话收尾了，但 xxx 还没归档」）。面板只做截断（超过约 40 字加省略号），不改写、不翻译——改写会让面板和值班单对不上号。

## Risks / Trade-offs

- **标题太长挤掉时间** → 先固定时间在前，标题截断在后；完整内容仍可点开对话看。
- **`lastError` 很久不清空，看着像一直坏** → 这是它的语义：下一次投递成功才清。用户可以点「打开对话」看监工自己怎么说。
- **本地化格式依赖浏览器语言** → 用 `zh-CN` 显式指定，避免英文系统下出现 `12:03 PM` 与中文文案混排。
